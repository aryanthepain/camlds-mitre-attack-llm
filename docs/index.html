Automated Mapping of Suricata Alerts to MITRE ATT&CK using LLM/RAG

Security Operations Centers face tens of thousands of low-level intrusion detection alerts daily. This project implements a deterministic Retrieval-Augmented Generation pipeline that translates raw Suricata eve.json alerts into verified MITRE ATT&CK Enterprise technique identifiers using dense embeddings and local LLM reasoning.

System Architecture

Five-Stage Data-Flow Pipeline

Every raw network event is normalized, embedded into vector space, cross-referenced against the MITRE ATT&CK Enterprise knowledge base, and resolved via candidate ranking or local LLM reasoning.

Stage 01
Raw Ingestion & Event Parsing
Recursively extracts eve.json lines where event_type == "alert". Extracts signature, protocol, ports, category, severity, and network metadata into a normalized text payload.
Module: src/prepare_dataset.py 
// Raw Suricata Alert Payload
{
  "timestamp": "2026-02-14T08:21:04.102Z",
  "event_type": "alert",
  "src_ip": "192.168.1.45",
  "dest_port": 80,
  "proto": "TCP",
  "alert": {
    "signature": "ET SCAN Nmap Scripting Engine User-Agent Detected",
    "category": "Attempted Information Leak",
    "severity": 2,
    "signature_id": 2009358
  }
}
Stage 02
Dense Vector Encoding
Constructs a contextual natural-language alert descriptor and computes a 384-dimensional normalized cosine embedding using all-MiniLM-L6-v2.
Dimension: 384-Float32 Normalized 
// Linearized Alert Representation & Embedding Output
text = "suricata alert signature: ET SCAN Nmap Scripting Engine User-Agent | category: Attempted Information Leak | severity: 2 | proto: TCP | app: http"

// Tensor Vector Representation
embedding = [
  -0.041829,  0.089124, -0.034512,  0.012891, 
  -0.071239, -0.019482,  0.056123, -0.098412, 
  /* ... 376 additional floating-point components ... */
]
Stage 03
ChromaDB Top-K Retrieval
Executes vector nearest-neighbor search over 626 MITRE Enterprise techniques compiled from official STIX JSON. Returns top-5 candidate techniques ranked by cosine similarity.
Module: src/build_vector_db.py 
// ChromaDB Query Result (Top Candidates)
[
  { "id": "T1046",     "name": "Network Service Discovery",    "similarity": 0.7842, "tactic": "discovery" },
  { "id": "T1595",     "name": "Active Scanning",             "similarity": 0.7410, "tactic": "reconnaissance" },
  { "id": "T1018",     "name": "Remote System Discovery",      "similarity": 0.6829, "tactic": "discovery" },
  { "id": "T1040",     "name": "Network Sniffing",             "similarity": 0.6105, "tactic": "credential-access" },
  { "id": "T1190",     "name": "Exploit Public-Facing App",   "similarity": 0.5891, "tactic": "initial-access" }
]
Stage 04 & 05
LLM Decision & Audit Output
In LLM mode (--llm ollama), candidates are evaluated with strict schema boundaries on local Qwen 2.5 7B. Emits verifiable JSON output with reasoning string and candidate provenance.
Execution: src/predict_rag.py 
// Structured Triage Prediction Output
{
  "alert_id": "faac131a20f6deab",
  "gold_technique_id": "T1046",
  "predicted_technique_id": "T1046",
  "predicted_name": "Network Service Discovery",
  "confidence": 0.7842,
  "topk_contains_gold": true,
  "reason": "Nmap Scripting Engine user-agent signifies active reconnaissance and network service discovery probing."
}

Understanding Baseline vs Specialized Embeddings

Generic sentence transformers (all-MiniLM-L6-v2) are trained on general English semantic similarity. While they successfully cluster high-semantic signatures like port scans to T1046, generic network transport anomalies require domain adaptation.

To close this gap without paying for commercial APIs, this repository includes a dedicated QLoRA fine-tuning notebook for Google Colab using Unsloth to adapt Qwen 2.5 directly to Suricata IDS signature syntax.
